# Скилл: Автономное развертывание и обход проблем установки стека Omni_Aion

Этот скилл предназначен для ИИ-ассистентов (Gemini) и инженеров для проведения автономной установки, расшифровки учетных данных Google Gemini и верификации стека **OmniRoute + AionUi + Gemini Farm** в среде Windows 11 / WSL2.

---

## 🎯 Назначение и Архитектурный контракт

1. **Развертывание с нуля («с 0»):**
   - Установка и конфигурирование Node.js 18+ и `@omniroute/core` в WSL2.
   - Развертывание проверенного автономного рантайма **AionUi 2.1.47** (`bundled-aioncore`, WebUI assets, плагины).
   - Восстановление и регистрация рабочих баз данных и всех авторизованных профилей Gemini.
2. **Механизм мастер-ключа (AES-256-GCM + PBKDF2 600k):**
   - Чувствительные данные (OAuth-токены Google, ключ шифрования `STORAGE_ENCRYPTION_KEY`, база `storage.sqlite` и `aionui-backend.db`) запечатаны в контейнере `vault.enc`.
   - **Принцип однократного ввода:** Мастер-ключ передается агенту **ТОЛЬКО ОДИН РАЗ** при первой установке/распаковке бандла на новой машине.
   - После успешной расшифровки учетные данные сохраняются в локальном защищенном хранилище WSL2. При последующих повседневных запусках сервисы стартуют **автоматически без запроса паролей**.
3. **Неприкосновенность сетевого контура Claude (:1015):**
   - Никакие операции развертывания OmniRoute или AionUi не имеют права модифицировать сокет `127.0.0.1:1015` или убивать связанные сессии Type-B Claude.

## 🚀 Протокол автономного выполнения для Gemini

Когда пользователь передает задачу:
> *«Вот мастер-ключ [ПАРОЛЬ], разверни Omni_Aion, восстанови аккаунты Gemini и протестируй работоспособность»*

Агент выполняет следующие шаги строго по алгоритму:

### Шаг 1. Определение файла бандла
Проверить каталог `dist/` в корне проекта:
```powershell
Get-ChildItem -Path "dist\*.hbin" | Sort-Object LastWriteTime -Descending | Select-Object -First 1
```
Если бандл отсутствует, собрать его:
```powershell
& ".venv\Scripts\python.exe" -c "import Omni_Aion; Omni_Aion.build_stack_bundle('<МАСТЕР_КЛЮЧ>')"
```

### Шаг 2. Запуск установки стека
Выполнить установку в неблокирующем режиме через CLI:
```powershell
& ".venv\Scripts\python.exe" "Omni_Aion\install_herdr_stack.py" --key "<МАСТЕР_КЛЮЧ>" --yes
```
*Либо через Python API:*
```python
import Omni_Aion
bundle = Omni_Aion.find_latest_bundle()
ok, msg = Omni_Aion.install_stack_bundle(master_key="<МАСТЕР_КЛЮЧ>", bundle_path=bundle)
```

### Шаг 3. Запуск верификации и самотестирования (Self-Test)
Сразу после установки запустить тестовый сценарий:
```powershell
& ".venv\Scripts\python.exe" "Omni_Aion\verify_stack.py"
```
Скрипт проверяет:
1. `http://127.0.0.1:20128/v1/models` (с заголовком `Authorization: Bearer sk-omniroute-secret` и обходом прокси).
2. `http://127.0.0.1:25808/api/auth/status`.
3. Реальный тестовый инференс через шлюз на модель `auto/best-fast`.

### Шаг 4. Прогон набора модульных тестов
```powershell
& ".venv\Scripts\python.exe" -m unittest Omni_Aion/test_omni_aion.py
```

## 🛠️ Матрица проблем при установке и методы их обхода (Troubleshooting)

### 1. Проблема: Зависание или нехватка памяти при распаковке архива (470+ МБ)
- **Симптом:** Передача архива через `wsl.exe bash -c "tar ... | base64"` виснет на несколько минут или вызывает `OutOfMemory`.
- **Причина:** Накладные расходы на кодирование сотен мегабайт в Base64 и передачу через стандартный поток вывода stdout в WSL interop.
- **Обход:** Использовать прямой потоковый доступ через сетевые UNC-пути Windows к WSL:
  `\\wsl.localhost\Ubuntu\tmp\...` или `\\wsl$\Ubuntu\tmp\...`
  В коде используется `zipfile.ZipFile(bundle_path).extract(..., unc_dest)`. Время распаковки сокращается с 6 минут до **11 секунд**.

### 2. Проблема: Локальные запросы падают с HTTP 502 Bad Gateway / Connection Refused
- **Симптом:** Попытка проверить `127.0.0.1:20128` или `127.0.0.1:25808` из Python или curl возвращает `502 Bad Gateway`.
- **Причина:** Переменные окружения `http_proxy`, `https_proxy`, `all_proxy` (направленные на порты 1015 или 11015) перехватывают локальный loopback-трафик.
- **Обход:**
  - В curl **всегда** добавлять `--noproxy '*'`:
    ```bash
    curl --noproxy '*' -s http://127.0.0.1:20128/v1/models -H "Authorization: Bearer sk-omniroute-secret"
    ```
  - В Python отключать прокси через `ProxyHandler({})` и выставлять `os.environ["no_proxy"] = "*"`.

### 3. Проблема: Повреждение базы AionUi («database disk image is malformed») и SQLite Locks
- **Симптом:** После копирования базы AionUi возвращает 500 ошибку или требует повторный логин.
- **Причина:** Копирование файла `aionui-backend.db` во время работы AionUi без учета открытых транзакций в `aionui-backend.db-wal` и `aionui-backend.db-shm`. Открытие файла по UNC из Windows блокирует SQLite на стороне Linux.
- **Обход:**
  - Захват базы при сборке бандла производить **только** через SQLite Online Backup API (`sqlite3.connect.backup()`) либо после выполнения `PRAGMA wal_checkpoint(TRUNCATE)`.
  - Все прямые операции с SQLite выполнять строго внутри окружения WSL2.

### 4. Проблема: Ошибка расшифровки токенов в OmniRoute (STORAGE_ENCRYPTION_KEY Mismatch)
- **Симптом:** OmniRoute запускается, но при обращении к профилям Gemini выдает ошибку расшифровки учетных данных или падает.
- **Причина:** Учетные данные в таблице `provider_connections` зашифрованы алгоритмом AES-GCM ключом `STORAGE_ENCRYPTION_KEY` из `~/.omniroute/.env`. Если сгенерировать новый `.env`, старая база `storage.sqlite` становится нечитаемой.
- **Обход:** Файлы `storage.sqlite` и `~/.omniroute/.env` упаковываются и восстанавливаются **синхронно** как единое целое внутри зашифрованного контейнера `vault.enc`.

### 5. Проблема: Преждевременное определение AionUi как «Offline»
- **Симптом:** Сразу после старта скрипт сообщает, что AionUi не запустился.
- **Причина:** Бинарник `bundled-aioncore` выполняет инициализацию модулей и миграцию таблиц в течение 9–18 секунд.
- **Обход:** Использовать цикл ожидания готовности (polling loop) минимум на 25 попыток с интервалом в 1 секунду по эндпоинту `/api/auth/status`.

### 6. Проблема: Ошибка 400 Bad Request при тестовом инференсе через OmniRoute
- **Симптом:** Запрос `POST /v1/chat/completions` с `model: gemini-2.5-flash` возвращает HTTP 400.
- **Причина:** В шлюзе OmniRoute зарегистрированы агрегированные виртуальные алиасы маршрутизации, а не сырые имена моделей.
- **Обход:** При проверке инференса адресовать запрос на алиас `auto/best-fast` или `auto/best-chat`:
  ```json
  {
    "model": "auto/best-fast",
    "messages": [{"role": "user", "content": "Ping"}],
    "max_tokens": 10
  }
  ```
