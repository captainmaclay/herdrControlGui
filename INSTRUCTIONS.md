# Herdr Control GUI (System Reference & Developer Guide)

Этот документ сформирован как исчерпывающий системный гайд (System Prompt Supplement) для разработчиков, а также **для других ИИ-агентов (Large Language Models)**, которые будут поддерживать, масштабировать или анализировать этот проект.

## 1. Концепция (Что это такое?)
`Herdr Control GUI` — это Python/Tkinter приложение, работающее на хосте Windows, созданное для безопасного управления, оркестрации и синхронизации ИИ-моделей (Claude Code / Gemini Farm) внутри изолированной среды WSL (Сюрбсистема Linux). 
Приложение является «панелью управления» (Backend-менеджером) для систем:
* **AionUi:** Пользовательский интерфейс и фреймворк агентов.
* **OmniRoute:** Локальный роутер, балансирующий нагрузку ИИ через карусель прокси.

Ключевая философия проекта: **Параноидальная безопасность.** Все конфиденциальные файлы хранятся с применением AES-256-GCM шифрования 99% времени, расшифровываясь (буквально на миллисекунды) исключительно в моменты синхронизации или манипуляций пользователя.

## 2. Карта Модулей и Архитектура

Приложение построено в виде легко связанных модулей (Loose Coupling). Главный файл `config_app.py` отвечает исключительно за графическое отображение и вызовы функций из независимых менеджеров:

### Файловая структура (Ключевые файлы)
* `config_app.py` — Ядро графического интерфейса (Tkinter). Управляет вкладками, вызывает методы, отвечает за State-память.
* `token_vault_manager.py` — **Самый критический модуль безопасности.** Ядро шифрования. Автоматически скрывает `.json` токены в `.enc` файлы. 
* `token_meta_cache.py` — Кеширует несекретную базу данных UI (срок годности, почту аккаунтов). Позволяет GUI отрисовывать списки токенов, **не расшифровывая хранилище**.
* `claude_oauth_manager.py` — Управляет связью с Anthropic. Маршрутизирует процесс авторизации Claude *строго через прикрепленный SOCKS5 (по умолчанию 1015)* для обхода агрессивного антифрода Anthropic.
* `gemini_manager.py` — Управляет фермой Google аккаунтов. Рассчитывает порты (1081+), выполняет очистку сессий.
* `integrations_manager.py` — Сердце интеграции. Пайплайны, которые делают инъекции в базы данных AionUi (`aionui-backend.db`) и поднимают роутинг OmniRoute.
* `backup_manager.py` — Система AES-GCM бэкапов. Генерирует архивы `.hbak` со всеми настройками и зашифрованными токенами для безопасного переноса между рабочими станциями. Отвечает за операцию полного сброса (Factory Reset).
* `extended_logger.py` — Глобальный хук перехвата `sys.stdout/stderr`. Пишет все дампы памяти, принты и крэши в ротируемый файл `extended.log` с лимитом в 5MB.
* `proxy_manager.py` / `settings_manager.py` — Управление JSON-конфигами, сохранение роутов, IP и настроек окружения.
* `i18n.py` — Система локализации. Двуязычный словарь (в проекте категорически запрещено "хардкодить" строковые литеры в GUI).

## 3. Глубокое погружение: Token Vault & Безопасность

**Для ИИ-агентов:** Если вы разрабатываете функционал, обращающийся к папкам `~/.claude/` или `~/.gemini/profiles/`, вы обязаны соблюдать парадигму хранилища!

Обычно токены находятся в файлах вида `antigravity-oauth-token.enc`. Оригинальные `.json` удалены с диска. 
Чтобы прочитать секреты, вам необходимо использовать контекстный менеджер (он сам возьмет из `.env` пароль и защелкнет замок обратно как только ваш скрипт выполнится):

```python
import token_vault_manager

with token_vault_manager.auto_unlock_context():
    # На эти миллисекунды файлы .enc в WSL превращаются в валидные .json
    ok, data = read_sensitive_token()
    do_some_magic()
# Как только блок with закрывается, менеджер принудительно шифрует их обратно.
```

**Metadata-driven GUI:** Не пытайтесь читать токены для отрисовки интерфейса! Если вам нужно показать e-mail пользователя в GUI, запросите его у `token_meta_cache.get_meta()`. Это не нарушает состояние Locked.

## 4. Глубокое погружение: Пайплайны Интеграции

Модуль `integrations_manager.py` — это точка соприкосновения `Herdr` и внешнего мира.

### 🟢 Интеграция Gemini (OmniRoute Round-Robin)
Когда вызывается `sync_gemini()`:
1. Запрашивается авто-разблокировка (Vault Unlock).
2. Скрипт сканирует все доступные профили (`account-1`, `account-2` и т.д.).
3. Проверяет доступность SOCKS5 портов на `127.0.0.1` (от 1081 и выше).
4. Прописывает локального провайдера `http://127.0.0.1:20128/v1` (OmniRoute) напрямую в базу SQLite UI-движка AionUi.
5. Делает пинг-тест через роутер. В случае получения ошибки `429 (Resource exhausted)` OmniRoute аппаратно переключит липкость сессии на другой свободный SOCKS порт (другой аккаунт) для бесшовного продолжения диалога пользователя.

### 🔵 Интеграция Claude (SOCKS5 Anti-fraud)
Когда вызывается `sync_claude()`:
1. Хранилище также разблокируется.
2. Подтягивается OAuth токен (`config.json`), проверяется остаток дней подписки.
3. В конфиги вносится жесткий сетевой **Killswitch**. Весь трафик к LLM обязан идти через прописанный `127.0.0.1:1015`. Если прокси упал, трафик должен быть сброшен. Попытка API вызова вне прокси приведет к моментальному теневому бану от Anthropic из-за смены AS (провайдера) / IP.
4. В SQLite базу AionUi встраивается команда `/claude`.

## 5. Гайдлайн для ИИ по написанию и изменению кода

Если вам (нейросети-разработчику) дают задание внести изменения в этот проект, **строго** следуйте этим архитектурным правилам:

1. **Терминальные субпроцессы (Shelling):** 
   - Не используйте `cmd.exe /c start`. Он ломает парсинг двойных/одинарных кавычек. 
   - При необходимости открыть черное окно консоли для ввода данных (например, OAuth), используйте прямой вызов conhost API (только Windows):
     `subprocess.Popen(["wsl.exe", "-d", distro, "bash", "-lc", bash_cmd], creationflags=16)` (где `16` — это `subprocess.CREATE_NEW_CONSOLE`).
2. **Локализация:** 
   - Если вы добавляете новую кнопку или Label, **запрещается писать текст на русском или английском в самом `config_app.py`**.
   - Добавьте ключ в файл `i18n.py` _(сразу в обе ветви словаря `"en"` и `"ru"`)_ и используйте вызов `t("key")`.
3. **Ошибки и UI Lock (Зависания):**
   - Бэкенд-операции (`wsl wget`, запросы к базам, бэкапы) могут занять продолжительное время. 
   - Вызовы `subprocess.run` всегда должны содержать `encoding="utf-8", errors="replace"`, иначе на Windows-системах выбросится `UnicodeDecodeError` при столкновении с кириллицей из консоли Линукса.
4. **Холодный старт:**
   - Не забывайте, что `sys.stdout` не существует, когда программа запущена как `pythonw.exe`. Любые логгеры (например `extended_logger.py`) обязаны проверять `sys.stdout is not None` перед попыткой записи.

Держите эти паттерны в памяти, и архитектура останется пуленепробиваемой. Действуйте!

## 6. Детальная спецификация модулей (Справочник по файлам)

Для полноценной интеграции и разработки необходимо понимать точную ответственность каждого `.py` файла в системе. Ниже приведено полное описание всех компонентов и их ключевых пайплайнов.

### `config_app.py` (Главный UI-Оркестратор)
*Ядро графического интерфейса пользователя (GUI). Построено на библиотеке `tkinter` без использования сторонних тяжелых фреймворков для максимальной портативности.*
* **Пайплайны:** Инициализация всех графических элементов (Табы: Роуты, Настройки, Интеграции, Бэкапы), привязка кнопок к функциям-менеджерам.
* **Ключевые механизмы:** Содержит механизмы `update_ui` (периодическое обновление данных), управляет `system tray` (сворачивание в трей), вызывает хук `ensure_locked()` при старте.

### `token_vault_manager.py` (Крипто-Сейф)
*Самый важный модуль защиты.*
* **Пайплайны:** Умеет забирать пароль из `.env`, сканировать папки WSL на наличие `*oauth-token` или `.credentials.json` и с помощью библиотеки `cryptography (AESGCM)` конвертировать их в бинарные `.enc` ключи.
* **Функции:** 
  * `lock_tokens()` / `unlock_tokens()` — ручное блокирование и разблокирование хранилища.
  * `auto_unlock_context()` — Python Context Manager (`with ...:`), который автоматически открывает токены перед опасной операцией (удаление, синхронизация) и гарантированно запечатывает их обратно при выходе из блока или при ошибке.

### `token_meta_cache.py` (Система кэширования UI)
*Связующее звено между зашифрованными данными и графическим интерфейсом.*
* **Пайплайны:** При разблокировке или чтении токенов "откусывает" все небезопасные ключи (`id_token`, секреты) и сохраняет чистую выжимку (Почта, статус, срок годности) в системный файл `.herdr_vault_meta.json`.
* **Функции:** `get_meta()`, `update_meta()`. Позволяет модулям отдавать информацию в `config_app.py` не расшифровывая сам сейф.

### `gemini_manager.py` (Автоматизация Google Gemini)
*Механизм управления профилями, токенами и OAuth сессиями сервиса Gemini AI.*
* **Пайплайны:** Обслуживает папку `~/.gemini/profiles/`. Умеет читать JWT-сокеты Google (декодирование base64 claim'ов) для получения точного времени `exp` (истечения токена) и отображения email-адресов.
* **Ключевые механизмы:**
  * Управляет инкрементальным назначением SOCKS портов (base `1081`).
  * `launch_add_account_terminal()` — открывает чистую консоль `wsl.exe`, пробрасывает SOCKS-прокси в `HTTP_PROXY` и запускает `gemini-oauth add`.
  * `switch_profile()` — переключает активный аккаунт в папке `antigravity-cli`.

### `claude_oauth_manager.py` (Автоматизация Anthropic Claude)
*Аналог Gemini-менеджера, но со строгими правилами антифрода для Anthropic.*
* **Пайплайны:** Управляет папкой `~/.claude/`. Вытаскивает сроки годности Refresh и Access токенов. 
* **Ключевые механизмы:** При запуске процесса `claude auth login` намертво привязывает терминал к "правильному" SOCKS порту (обычно `1015`), чтобы Claude зафиксировал IP, с которого разрешена дальнейшая работа.

### `integrations_manager.py` (API инъекций и Синхронизаций)
*Движок передачи конфигураций из Herdr напрямую в агентов и маршрутизаторы.*
* **Пайплайн `sync_claude()`:** Снимает блокировку -> Обновляет `manifest.json` AionUi до `2.1.280` -> Регистрирует команду `/claude` напрямую в SQLite-базе `aionui-backend.db` -> Принудительно ставит Killswitch и Proxy в настройки.
* **Пайплайн `sync_gemini()`:** Снимает блокировку -> Пробегается по всем портам профилей 1081+ (Socket check) -> Пишет провайдера `OmniRoute Gemini Farm` в SQLite-базу AionUi -> Делает тестовый REST API HTTP ping на `http://127.0.0.1:20128/v1/chat/completions`, заставляя роутер проработать Round-Robin логику.

### `backup_manager.py` (Машина состояний и Архивации)
*Движок полного резервирования и функции "Судного дня" (Factory Reset).*
* **Пайплайны:** Берет базу SQLite, папку `.claude/`, настройки `.env` и `.json`, зипует их и шифрует (все тем же AESGCM) в один монолитный файл `.hbak`. Затем умеет разворачивать его в другой операционной системе.
* **Функция `wipe_all_data()`:** Тотальный сброс. Рекурсивно очищает все `~/.gemini`, `~/.claude`, удаляет БД, стирает историю стратегий, обнуляет `.env` и чистит логи, оставляя программу в полностью девственном (clean-slate) состоянии.

### `proxy_manager.py` & `settings_manager.py` (Конфигураторы)
*Два легковесных модуля хранилищ настроек.*
* `proxy_manager.py` читает/пишет `proxies.json`. Умеет пинговать прокси через `ip-api.com`. Хранит данные о задержках и геолокации.
* `settings_manager.py` читает/пишет `settings.json`. Хранит базовые настройки портов, темы UI и биндингов аккаунтов.

### `extended_logger.py` (Глобальный Око-Логгер)
*Хук-перехватчик системного уровня.*
* **Пайплайны:** Перенаправляет `sys.stdout` (принты), `sys.stderr` и `sys.excepthook` (ошибки парсинга, трейсбеки) в ротируемый (ограниченный по весу в 5MB) файл `extended.log`. Гарантирует, что ни одна фоновая ошибка потока или субпроцесса не потеряется, даже если приложение запущено в "тихом" оконном режиме `pythonw.exe`.

### `sync_manager.py` & `strategy_manager.py` (Телеметрия)
*Аналитика использования аккаунтов для обеспечения безопасности.*
* `strategy_manager.py` пишет в `strategy_history.json` каждый запуск ИИ. Он считает не количество входов, а **суммарное время** в секундах, которое аккаунт провел в конкретной стране (IP/регионе).
* Это предотвращает блокировки (если ИИ аккаунт всегда работал в Финляндии, система предупредит вас, если вы попробуете пустить его через Швецию).

### `aionui_claude_bridge.py`
*Сервисный мини-скрипт. Является мостом-диагностом.*
Выполняет Python-код напрямую **внутри** подсистемы WSL (создает субпроцесс), заставляя Линукс проверить свои внутренние пути, версии Node.js, порты TCP 20128/1015 и вернуть готовый JSON-статус в графический интерфейс Windows.

### `i18n.py` (Локализатор)
Модуль-словарь. Вся программа полностью двуязычна. Вызов функции `t("key")` ищет строку в словаре `en` или `ru`. Все изменения интерфейсов должны проходить исключительно через этот файл.
