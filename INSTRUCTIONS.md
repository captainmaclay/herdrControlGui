# Herdr Research Control Center: Системное руководство разработчика

Этот документ является исчерпывающим системным описанием архитектуры (System Specification) для исследователей, инженеров и **ИИ-агентов (LLM)**, поддерживающих, анализирующих и развивающих эту платформу.

---

## 1. Научно-инженерная концепция проекта

### Исследовательская гипотеза
Платформа создана для проверки фундаментальной гипотезы в области распределённых мультиагентных систем:
> **Гипотеза:** *Ансамбль гетерогенных, узкоспециализированных сабагентов (worker nodes), взаимодействующих через оркестратор с изолированными сетевыми топологиями, решает комплексные аналитические и инженерные задачи точнее, быстрее и стабильнее, чем единая монолитная старшая модель (Frontier LLM).*

### Зачем нужна сетевая изоляция рабочих узлов?
Для получения статистически достоверного и воспроизводимого знания при проведении сравнительных бенчмарков:
1. **Исключение сетевой интерференции:** При одновременном выполнении десятков подзадач сабагентами общий сетевой сокет создает очередь ожидания (Head-of-Line Blocking) и искажает измерения задержки (TTFT — Time To First Token). Изоляция каждого узла на свой персональный порт (1081, 1082, 1083...) гарантирует чистоту экспериментальных метрик.
2. **Изоляция контекстного кэша:** Каждый узел работает в независимом пространстве состояний, исключая кэш-коллизии и утечки промежуточных рассуждений между параллельными потоками.
3. **Отказоустойчивость эксперимента (Fail-Safe Circuit Breaker):** Защитные шлюзы гарантируют, что трафик тестового узла никогда не утечет в неконтролируемые сетевые маршруты, сохраняя валидность собранных телеметрических данных.
4. **Бесперебойное тестирование высокой нагрузки:** При длительных бенчмарк-сессиях исчерпание квот окна пропускной способности автоматически компенсируется переключением на резервный исследовательский узел через алгоритм Round-Robin.

Платформа выступает связующим звеном и бэкенд-менеджером для:
* **AionUi:** Пользовательский интерфейс и оркестратор мультиагентных графов выполнения.
* **OmniRoute:** Высокопроизводительный распределитель нагрузки и балансировщик запросов между исследовательскими узлами.

## 2. Карта модулей и архитектура

Архитектура построена на принципах слабой связанности (Loose Coupling). Все классы, функции и переменные сохраняют неизменные имена для гарантированной стабильности runtime:

### Ключевые модули:
* **`config_app.py`** — Графический интерфейс исследователя (Tkinter). Управляет визуализацией телеметрии узлов, переключением топологий и мониторингом состояния экспериментов.
* **`token_vault_manager.py`** — Криптографический модуль управления чувствительными артефактами. Обеспечивает концепцию Zero-Trust: учетные данные узлов хранятся в зашифрованном виде (`.enc`, AES-256-GCM) и расшифровываются исключительно на время передачи вызова. Устойчив к прерываниям ввода-вывода WSL UNC (`WinError 995`).
* **`token_meta_cache.py`** — Кеширует метаданные узлов (срок действия сессии, идентификатор ноды) для отображения в GUI без необходимости расшифровки артефактов.
* **`gemini_manager.py`** — Управляет пулом исследовательских узлов Gemini. Рассчитывает привязку портов (1081+), контролирует жизненный цикл сессий и проводит санитарную очистку временных директорий.
* **`claude_oauth_manager.py`** / **`claude_manager.py`** — Управляет связью с узлами Anthropic. Маршрутизирует запросы через выделенный канал для прецизионного замера задержки.
* **`integrations_manager.py`** — Модуль интеграции. Конфигурирует связи в базах данных AionUi (`aionui-backend.db`) и поднимает распределение нагрузки в OmniRoute (`storage.sqlite`).
* **`strategy_manager.py`** — Анализ телеметрии сетевых путей. Оценивает кумулятивное время работы узлов, региональное распределение задержек и стабильность каналов связи.
* **`backup_manager.py`** — Создание эталонных снимков окружения (Golden Reference) с криптографической верификацией для переноса стенда тестирования на другие машины.
* **`extended_logger.py`** — Перехват `sys.stdout/stderr` и ведение кольцевого журнала событий бенчмарка.
* **`proxy_manager.py`** / **`settings_manager.py`** — Управление таблицами маршрутизации узлов и глобальными параметрами исследовательской среды.
* **`i18n.py`** — Модуль локализации интерфейса.
* **`watchdog_manager.py`** — **aiWatcher**, встроенный сторож сервисов WSL2 (бывшее отдельное приложение `D:\My files\aiWatcher`). Класс `WatchdogService`: фоновый поток, каждые `interval` с выполняет `check_cmd` каждого сервиса через `wsl.exe bash -lc` и при сбое `start_cmd`; период прогрева, таймауты, флаг обслуживания, обнаружение внешнего aiWatcher. Конфиг `watchdog_config.json`. Карточка «aiWatcher» на странице «Маршруты» (`_build_aiwatcher_card` в `config_app.py`) заменила карточку «Herdr Multiplexer в WSL2»; сторож запускается в `main()` (не в конструкторе окна, чтобы тесты не трогали WSL). Документация: [docs/AIWATCHER.md](docs/AIWATCHER.md).

## 3. Криптографическая безопасность экспериментальных данных (Token Vault)

Все файлы аутентификации исследовательских узлов шифруются на диске: `*.enc`. В открытом виде (`.json`) токены на диске не сохраняются.

Для взаимодействия с узлами используется контекстный менеджер безопасной разблокировки:
```python
import token_vault_manager

with token_vault_manager.auto_unlock_context():
    # На период выполнения блока токены кратковременно становятся доступны в оперативной памяти
    ok, data = read_sensitive_token()
    execute_benchmark_step()
# По завершении блока менеджер немедленно шифрует файлы обратно
```

## 4. Пайплайны интеграции с бенчмарк-кластером

### 🟢 Интеграция узлов Gemini в OmniRoute (Round-Robin Farm)
При запуске `sync_gemini()`:
1. Запрашивается кратковременная разблокировка хранилища учетных данных.
2. Проводится аудит сетевых портов рабочих узлов (1081, 1082, 1083...).
3. В базе данных OmniRoute регистрируются сокеты в `proxy_registry` и привязки 1:1 в `proxy_assignments`.
4. Формируется комбо-маршрут `gemini-farm` с политикой балансировки `round-robin`.
5. По завершении синхронизации Сейф Токенов блокируется обратно.

### 🟣 Интеграция Claude Code в AionUi
Связывает рабочий узел Claude с графическим интерфейсом AionUi через унифицированный протокол ACP (`agent_type = 'acp'`), обеспечивая автоматический перезапуск упавших сессий и сохранение протоколов бенчмарка.

## aiWatcher — встроенный сторож сервисов WSL2

Краткая памятка (полная версия: [docs/AIWATCHER.md](docs/AIWATCHER.md)):

1. **Где:** вкладка «Маршруты», первая карточка **«👁 aiWatcher»**.
2. **Что делает:** каждые 5 с проверяет AionUi (:25808) и OmniRoute (:20128) в WSL2 и запускает упавший сервис.
3. **Управление:** «▶ Включить / ⏸ Выключить сторож», галочки сервисов, «🔄 Проверить сейчас», журнал событий.
4. **Настройки:** `watchdog_config.json` рядом с программой (`watcher_on`, `interval`, `grace_seconds`, `apps.*.enabled/check_cmd/start_cmd`).
5. **Ремонт базы AionUi:** скрипты `aionUi_helper` ставят флаг `~/.aionui-web/.maintenance`, и сторож на это время AionUi не трогает.
6. **Старый отдельный aiWatcher:** если он запущен, встроенный на паузе. Кнопка «Остановить внешний aiWatcher» завершает его и отключает его автозапуск (`ai_watcher_autorun.vbs` → `.disabled`).
6а. **Экран входа AionUi «Connection failed»:** сторож проверяет `/api/auth/status` и при 502 сам делает чистый перезапуск (не чаще раза в 10 мин). Если не помогло — кнопка «🛠 Починить базу AionUi», затем «♻ Перезапустить AionUi (чисто)». Причины: `docs/AIWATCHER.md`, раздел 2а.
7. **Тесты:** `python -m pytest test_watchdog_manager.py test_aiwatcher_card.py test_ui_command_refs.py test_app_ui.py -q`.
