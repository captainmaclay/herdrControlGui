# Herdr Token Integration Guide (AionUi & OmniRoute)

Этот документ предназначен для систем и исследователей, разрабатывающих интеграцию мультиагентных симуляторов (таких как AionUi) и прокси-роутеров (OmniRoute) с ядром Herdr. 

Архитектура Herdr выстроена вокруг максимальной безопасности и чистоты экспериментов. **99% времени сессионные токены хранятся на жестком диске в зашифрованном виде**. Интегрируемые сервисы должны учитывать механизм `Token Vault` (Хранилище токенов) и правильно с ним взаимодействовать.

## 1. Шифрование и Token Vault (Декодирование "на лету")

Все конфиденциальные токены узлов Type-A и Type-B шифруются по стандарту:
* **Алгоритм:** `AES-256-GCM` 
* **Деривация ключа:** `PBKDF2-HMAC-SHA256` (соль 16 байт)
* **Структура зашифрованного файла (`.enc`):** `Соль (16 байт) + Nonce/IV (12 байт) + Шифротекст с GCM-тегом`
* **Дополнительные данные (AAD):** `HRDRTK01`
* **Мастер-ключ (Пароль):** берется из системного файла `.env` в корневой директории Herdr.

### Поведение интеграции OmniRoute / AionUi
Так как OmniRoute является балансировщиком и работает в фоне, у интеграций есть два пути взаимодействия с токенами:

**Путь А (Векторный вызов дешифровки перед стартом)**
OmniRoute не должен пытаться дешифровать файлы самостоятельно. На стороне `herdrControlGui` реализован CLI и модули:
1. При старте активной сессии OmniRoute (или скриптом AionUi), вызывается команда разблокировки: 
   `python3 token_vault_manager.py --unlock <пароль_из_.env>`
2. Токены материализуются на диске в виде обычных JSON-файлов в сессионных директориях WSL2.
3. OmniRoute/AionUi начинает работу.
4. После остановки балансировщика, вызывается:
   `python3 token_vault_manager.py --lock <пароль>`

**Путь Б (Автоматическая разблокировка через Интегратор GUI)**
В `integrations_manager.py` уже встроена логика: если исследователь нажал «Синхронизировать», скрипт сам подставит пароль из `.env`, временно расшифрует токены и передаст в базу данных чистые сессионные данные.

## 2. Интеграция с пулом узлов Type-A (OmniRoute)

В условиях исследовательских стресс-тестов лимиты пропускной способности узлов ограничены по контексту (TPD / RPD).
OmniRoute реализует **мгновенный Round-Robin с отвязкой сессий (session un-stickiness)**:

* **Алгоритм перехвата (Circuit Breaker):** На каждый запрос роутер отслеживает ответы API.
* **Триггер исчерпания пропускной способности (429):** Если узел возвращает статус `429` с превышением квоты, этот профиль помечается как исчерпавший окно пропускной способности.
* **Переключение (Failover):** Текущий узел временно переводится в резерв, и OmniRoute разрывает липкость. Следующий запрос внутри *того же самого диалога* направляется на резервный узел (SOCKS порт 1082) в прозрачном режиме, гарантируя непрерывность проведения бенчмарка.
* Регулярное выражение (RegEx) для триггера `429` обязано включать строку: `/resource has been exhausted \(e\.g\. check quota\)/i`.

## 3. Интеграция специализированных узлов Type-B (Сетевая изоляция сокетов)

Для исключения интерференции очередей сокетов хоста и корректного замера задержек:

**Требования для интеграции модулей AionUi:**
1. AionUi (вызывающий клиент рабочего узла) осуществляет запросы строго через калиброванный сетевой шлюз.
2. Все сетевые запросы узла пробрасываются строго через выделенный SOCKS5/HTTP сокет, привязанный к текущей сессии (по умолчанию `127.0.0.1:1015` / `127.0.0.1:11015`).
3. Интеграция транслирует `HTTP_PROXY`, `HTTPS_PROXY` и `ALL_PROXY='socks5h://127.0.0.1:1015'` в окружение `wsl` перед запуском процесса агента, чтобы сессионный поток и диалог происходили в детерминированном сетевом окружении.
